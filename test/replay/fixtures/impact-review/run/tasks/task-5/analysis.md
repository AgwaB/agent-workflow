The change is dormant when the environment variable is unset or blank: the real API object is returned unchanged, and injected test APIs bypass the seam. Existing workflow records, durable-barrier formats, and subagent artifact layouts are not migrated. The new persistence consists of calls.jsonl and api-surface.json.

**Outcome recording now participates in lifecycle correctness.** Arguments are projected before invocation; outcomes are projected and synchronously appended before reaching the caller. An append failure after a successful launch, release, revoke, or interrupt therefore reports failure despite an already-performed effect. Recording an API exception can also replace that exception with a recorder failure.

This matters concretely to backend state: the generic launch-error path returns the task to pending before recording a handle, and barrier failures trigger provisional-worker interruption. Refresh failures also prevent successful status observations from reaching normal processing. Existing launch-authority, correlation-recovery, and barrier protections remain; duplicate execution is not established, but additional ambiguous-outcome and recovery paths are introduced. Recording is not transactional with those effects.

**Configuration and failure state are cached.** The first real import resolution evaluates the environment and creates one shared wrapper. Concurrent callers reuse that promise, avoiding duplicate initialization within this module instance. Subsequent environment changes neither enable nor disable recording nor switch directories. Newly possible initialization failures—such as unwritable recording files—leave a rejected cached promise, even after permissions or environment configuration are corrected.

**Directory ownership is the main concurrency assumption.** Within one wrapper, sequence allocation is synchronous and unique; asynchronous completions can legitimately appear out of sequence in the file, and replay sorts by seq. Across wrappers or restarts, however, seq resets while calls.jsonl remains append-only. Surface metadata is independently overwritten. Although pid is recorded, replay does not use it to partition histories. The capture helper replaces captured run trees without clearing calls, so directory reuse can combine old calls with a new filesystem snapshot. Worker environment inheritance makes descendant activation possible, but actual competing writers were not demonstrated.

**The artifacts are observations, not a durable execution journal.** No entry is persisted when a call starts. A process exit can omit an effectful call entirely, and there is no flush/drain interface for pending calls. Writes have no explicit fsync or crash-recovery protocol. Replay parses every nonempty line, so a partial trailing record causes parsing failure rather than recovery.

**Projection changes recording fidelity, not ordinary live payloads.** Original arguments and successful values are forwarded when recording succeeds. Recordings nevertheless collapse undefined results into null, replace unsupported values with markers, reshape Maps/Sets, and retain only selected Error fields. Replay reconstructs ordinary JSON and generic errors, not original types. These new artifacts have no embedded format version; fixture compatibility depends on recorder/consumer agreement rather than a migration mechanism.

Projection itself is not universally safe. For example, an Error whose code refers to itself recursively re-enters Error projection before cycle detection. Invalid Dates and throwing getters also escape serialization. Depending on timing, these failures prevent invocation or conceal an existing outcome.

Finally, recording duplicates potentially sensitive task/system prompts and other API data onto disk using default filesystem permissions. There is no redaction, retention policy, size bound, or rotation. Repeated polling grows storage and incurs synchronous serialization/write work; downstream compaction does not reduce recording-time costs.

Before relying on captures as references, require a fresh, exclusive directory and settled calls, establish retention/content handling, and test filesystem failures, directory reuse, concurrent completion ordering, and exceptional projections. The inspected recorder test covers basic forwarding and serialization only. Confidence is high in these static paths; runtime frequency and actual multi-process directory sharing remain unverified.
